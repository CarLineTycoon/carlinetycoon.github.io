    布局（.clt-layout.json）¶

    布局文件包含一个场地中某一楼层的墙壁、区域和对象。导入时，游戏会按正常价格并遵循手动建造时的规则放置每个部件。

    架构：layout.schema.json · 示例：example_layout.zip

    简便方法：从游戏导出¶

    打开建造 → 场地，选择场地和楼层，然后按导出布局。游戏会将文件写入模组文件夹下的 exports 文件夹，文件名根据场地和楼层生成；工厂底层的文件名为 industrial_1.clt-layout.json。

    示例¶

    {
  "format": "car-line-tycoon.layout",
  "formatVersion": 1,
  "gameVersion": "0.6.0",
  "id": "small_hall",
  "name": "Small hall",
  "site": "industrial",
  "floor": 0,
  "objects": [
    { "definition": "split", "x": 25, "z": 14, "rotation": "North" },
    { "definition": "belt", "x": 20, "z": 7, "rotation": "East" }
  ],
  "walls": [
    { "x1": 18, "z1": 5, "x2": 42, "z2": 5 },
    { "x1": 42, "z1": 5, "x2": 42, "z2": 35 },
    { "x1": 42, "z1": 35, "x2": 18, "z2": 35 },
    { "x1": 18, "z1": 35, "x2": 18, "z2": 5 }
  ],
  "areas": [
    { "kind": "Production", "x": 18, "z": 5, "width": 24, "depth": 30 }
  ]
}

    字段¶

    字段 类型 必需 说明
    format 字符串 是 固定为 car-line-tycoon.layout。
    formatVersion 整数 是 1。
    gameVersion 字符串 否 生成文件的游戏版本，仅供参考。
    id 字符串 是 文件 ID。格式为 ^[a-z][a-z0-9_]{2,40}$。
    name 字符串 否 布局名称。
    site 字符串 是 industrial（工厂）或 urban（展厅）。
    floor 整数 否 楼层；底层为 0。工厂只有楼层 0；展厅楼层范围为 0 至 5。默认值为 0。
    objects 对象 数组 是 最多 5000 个，可以为空。
    walls 墙壁 数组 是 最多 5000 个，可以为空。
    areas 区域 数组 是 最多 5000 个，可以为空。

    位置使用场地建造网格中的格子表示；每格为 2 米。你可以从游戏中导出布局，以查看自己厂房的坐标。

    对象¶

    字段 类型 必需 说明
    definition 字符串 是 对象 ID，例如 belt 或 split。参见对象。
    x 整数 是 对象在 x 轴上的格子坐标。
    z 整数 是 对象在 z 轴上的格子坐标。
    fineX 整数 否 独立家具在格子内的偏移量，以格子的十六分之一为单位，范围为 0 至 15。
    fineZ 整数 否 z 轴上的同类偏移量。
    rotation 字符串 是 North、East、South 或 West，大小写不限。

    墙壁¶

    连接两个网格点的直墙。

    字段 类型 必需 说明
    x1、z1 整数 是 起点。
    x2、z2 整数 是 终点。

    区域¶

    字段 类型 必需 说明
    kind 字符串 是 Production、Warehouse、Services、Yard、Commercial 或 Workshop，大小写不限。
    x、z 整数 是 区域的第一个格子。
    width 整数 是 宽度，以格子计，至少为 1。
    depth 整数 是 深度，以格子计，至少为 1。

    导入如何建造布局¶

    游戏会按照以下顺序，在文件指定的场地和楼层建造各部件：

    1. 厂房。墙壁围成封闭矩形时，游戏会使用建造菜单中的墙矩形工具，将整个矩形建为一栋厂房。四边墙壁会一起计为已放置或已跳过。
    2. 内部墙壁。其他墙壁会逐面建造。单面墙只能建在厂房内部。
    3. 区域。
    4. 对象。

    每个部件都按正常价格计费，并遵循正常建造规则。如果游戏拒绝建造某个部件（格子已占用、资金不足、对象未知或需要研究、场地尚未归你所有），就会跳过该部件并继续。最后，游戏会显示布局已导入：已放置 N 个，已跳过 M 个。

    每个布局文件应只包含一栋厂房。如果文件中的墙壁未围成一个包围所有墙壁的封闭矩形，游戏会将它们逐面建造；已有厂房外的墙壁会被跳过。

    布局不包含的内容¶

    布局文件只包含建造内容。员工、车型、库存、研究和资金均沿用玩家游戏中的现有状态。

    游戏读取文件时的检查¶

    • 文件头和 id，
    • site 必须存在，且 floor 大于或等于 0，
    • objects、walls 和 areas 必须存在，每项最多 5000 个，
    • 每个对象都必须包含 definition 且其 rotation 有效，fineX／fineZ 的值必须在 0 至 15 之间，
    • 每个区域都必须包含有效的 kind，并且 width 和 depth 必须为正数。

    其余内容会在导入时逐个部件检查。
