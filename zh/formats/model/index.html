    车型（.clt-model.json）¶

    车型文件保存设计工作室中的设计：部件、颜色、颜色方案和选装套件。导入时，游戏会根据自带目录计算价格、性能和生产时间等数据，因此车型文件不能自行提供这些数值。

    架构：model.schema.json · 示例：example_model.zip

    简便方法：从游戏导出¶

    打开设计方案页面，选择一个车型，然后在详情中按导出车型。游戏会在模组文件夹中写入文件 exports/<model_name>.clt-model.json（车型名称使用小写形式，并以下划线分隔），然后显示路径。将文件复制到你的模组文件夹中，再在那里编辑。

    示例¶

    以下为简化文件示例（导出的文件会列出每个部件和全部七个颜色通道）：

    {
  "format": "car-line-tycoon.model",
  "formatVersion": 1,
  "gameVersion": "0.6.2",
  "id": "harbour_coupe",
  "name": "Harbour Coupe",
  "parts": [
    { "category": "body", "part": "Body_Taxi" },
    { "category": "bonnet", "part": "Bonnet_Taxi" },
    { "category": "chassis", "part": "Chassis_T_Wider" },
    { "category": "wheels", "part": "Wheel_Taxi_Stamp" },
    { "category": "motor", "part": "Motor_Bucket" }
  ],
  "colors": [
    { "channel": "body", "value": "#2F5D8A", "finish": 1 },
    { "channel": "trim", "value": "#C4C6C7" }
  ],
  "schemes": [
    {
      "id": "default",
      "name": "",
      "colors": [
        { "channel": "body", "value": "#2F5D8A", "finish": 1 },
        { "channel": "trim", "value": "#C4C6C7" }
      ]
    }
  ]
}

    字段¶

    字段 类型 必需 说明
    format 字符串 是 固定为 car-line-tycoon.model。
    formatVersion 整数 是 1。
    gameVersion 字符串 否 生成文件的游戏版本，仅供参考。
    id 字符串 是 文件 ID。格式为 ^[a-z][a-z0-9_]{2,40}$。
    name 字符串 否 车型名称。导入时会将其用作新车型的名称。
    parts 部件 数组 是 汽车部件，每个类别一个；至少包含一个部件。
    colors 颜色 数组 否 车型默认颜色；每个通道最多一项。
    schemes 方案 数组 否 车型的颜色方案。
    packages 套件 数组 否 选装套件（发动机、装甲、武器）。

    部件¶

    字段 类型 必需 说明
    category 字符串 是 部件类别，例如 body、wheels 或 motor。参见部件类别。
    part 字符串 是 游戏目录中的部件 ID。

    目录中有数百种部件，设计工作室会判断部件之间是否兼容。请在设计工作室中组装汽车并导出，然后从导出的文件中复制各部件的 ID。

    颜色¶

    字段 类型 必需 说明
    channel 字符串 是 body、roof、interior、trim、chassis、wheels 或 powertrain。
    value 字符串 是 #RRGGBB 或 #RRGGBBAA，使用十六进制表示。
    finish 整数 否 漆面效果的数值：0普通、1金属、2哑光、3珠光、4闪片、5镀铬。普通漆面可省略此字段。

    只有 body、roof、trim 和 wheels 支持普通以外的漆面效果。要使用特殊漆面效果，玩家的公司还必须完成相应的漆面研究。

    注意

    车型文件用数字保存漆面效果。涂装文件用名称保存。两者使用同一组漆面效果。

    方案¶

    字段 类型 必需 说明
    id 字符串 否 方案在车型中的 ID。导出文件中的第一个方案为 default，并重复默认颜色。
    name 字符串 否 方案名称。
    colors 颜色 数组 是 方案的颜色。

    多个方案需要玩家的公司完成颜色方案研究。

    套件¶

    字段 类型 必需 说明
    id 字符串 是 套件 ID。
    version 整数 是 套件版本，至少为 1。
    kind 整数 是 0发动机、1装甲、2武器。
    parts 部件 数组 是 套件新增或替换的部件。
    removals 字符串数组 否 套件移除的部件类别。

    游戏检查的内容¶

    读取模组文件夹时，游戏会检查文件头、id，并确认 parts 至少包含一项。

    在导入车型中选择文件后，设计方案页面会显示与粘贴设计相同的预览，并检查其余内容：

    • 每个部件都存在于目录中，且与周围部件兼容，
    • 每种颜色都使用已知通道和有效值，
    • 每个套件都适用于该车型。

    预览还会列出公司尚未解锁的部件（需要完成研究或达到后续时代）。文件未通过检查时，会显示与粘贴设计未通过检查时相同的提示。

    提示¶

    • 文件名由你决定。导入列表会显示去掉扩展名后的文件名。
    • 若要分享多个车型，可将它们放在同一个 model 模组中，例如存入 models/ 子文件夹。
    • 设计方案页面上的复制为文本和粘贴设计使用相关的文本格式 car-line-tycoon.design。模组应使用车型文件：它们包含 ID 和通用文件头。
