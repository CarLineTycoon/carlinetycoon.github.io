    声音¶

    通用版本 2 清单文件也支持 lua.v1。混合合集会同时声明 assets.audio.v1 和 lua.v1；音频文件加载完成后才会启动其中的脚本。 有关脚本启用和成就规则，请参见 Lua 指南。

    模组可以用自定义声音替换游戏自带的两种提示音：confirm 和 research。声音文件可以是 WAV 或 OGG，需在模组的 mod.json 中声明，并将 formatVersion 设为 2。

    两个小型示例模组展示了完整用法：example_audio.zip（WAV 铃声，用作 研究完成提示音）和 example_audio_ogg.zip（OGG Vorbis 滴答声，用作 确认提示音）。

    含声音的模组¶

    {
  "format": "car-line-tycoon.mod",
  "formatVersion": 2,
  "gameVersion": ">=0.6.4",
  "id": "harbour_audio",
  "version": "1.0.0",
  "name": { "en": "Harbour Audio", "it": "Suoni del porto" },
  "authors": ["Example Author"],
  "type": "pack",
  "requires": ["assets.audio.v1"],
  "assets": [
    {
      "id": "research_bell",
      "kind": "audio",
      "path": "audio/research_bell.wav",
      "license": "CC0-1.0",
      "author": "Example Author"
    }
  ],
  "audioBindings": [
    { "cue": "research", "asset": "research_bell", "gainDb": -3 }
  ]
}

    文件夹结构如下：

    Mods/
  harbour_audio/
    mod.json
    audio/
      research_bell.wav

    字段说明见清单文件页面。简要说明如下：

    • requires 列出模组所需的功能。声音模组需要 assets.audio.v1。
    • assets 用于声明每个文件。每项资源都有 id、值为 audio 的 kind、模组文件夹内的 path，以及文件的 license 和 author。也可以选择提供包含许可文本的 licenseFile。
    • audioBindings 指定各提示音使用的资源，并设置 -24 至 0 之间的 gainDb。
    • 含资源的模组，其 type 为 pack。合集也可以包含五种 JSON 文件格式中的任意格式。

    合集至少需要包含一项游戏可用内容：JSON 文件，或带绑定的声音。仅含声音的合集也可以正常使用，无需包含 JSON 文件。

    提示音¶

    提示音 cue 播放时机
    确认 confirm 使用游戏的确认按钮确认操作时。
    研究完成 research 一项研究完成时。每项完成的研究播放一次。开始或取消研究时不会播放声音。

    一个模组最多可为一个提示音绑定一个声音，且总共最多绑定两个提示音。模组停用或声音无法加载时，该提示音会继续使用游戏自带声音。

    声音文件¶

    允许的内容
    格式 WAV（RIFF、PCM、16 位、小端序）以及包含单条 Vorbis 音频流的 OGG
    不支持 Opus、浮点样本或 ADPCM 格式的 WAV、RF64、包含多条流的 OGG
    采样率 22050、44100 或 48000 Hz
    声道 1（单声道）或 2（立体声）
    时长 0.05 至 5 秒
    文件大小 最大 2 MiB
    解码后大小 一个模组中所有已绑定声音以 32 位数值存储的样本总量，最多 8 MiB
    路径 小写字母、数字、_、- 和 .；文件夹层级用 / 分隔；最多四段、总长最多 128 个字符；扩展名为 .wav 或 .ogg

    模组的其他限制：模组文件夹内最多 256 个文件（最多三层子文件夹）、64 项资源、2 个音频绑定；清单文件最大 256 KiB，最多嵌套 16 层，单段文本不超过 4096 个字符，且属性不得重复。所有启用的模组声明的文件总量最多为 512 MiB，其中最多使用 32 个含资源的模组；按 ID 排序靠后的模组会保持停用，并显示相应提示。

    游戏通过受限读取器读取每个已声明文件一次：不允许绝对路径、..、驱动器名或流名称、Windows 保留名称，也不允许路径中出现链接或目录联接。

    响度¶

    音效建议控制在约 -18 LUFS，真峰值低于 -1 dBTP。游戏加载声音时会测量每个声音的采样峰值和 RMS 电平；峰值高于 -1 dBFS 或 RMS 高于 -18 dBFS 时，游戏会降低音量。音量较低的声音不会被调高。之后游戏会应用你的 gainDb，范围为 -24 至 0。

    游戏降低声音音量时，模组页面会显示降低幅度。磁盘上的声音文件不会被修改。

    试听和使用声音¶

    模组页面上，含声音的模组为每个已绑定提示音提供一个试听按钮。按钮会按音效音量播放声音，并遵循静音状态和游戏窗口焦点：游戏静音或窗口未获得焦点时不会播放。你可以试听已停用模组的声音。

    启用的模组声音会用于更改后开始或载入的游戏。

    两个模组绑定同一提示音¶

    两个启用的模组绑定同一提示音时，两个模组仍然有效。该提示音会使用游戏自带声音，两个模组都会显示提示音共用的注意事项。只被其中一个模组绑定的提示音会继续播放该模组的声音。停用其中一个模组后，另一个模组的声音便会播放。

    模组页面上的错误和注意事项¶

    模组出现问题时，对应行会显示为红色。该行会显示首个错误：文件、错误代码、游戏检测到的值和限制。详情会打开最多包含 20 条错误和注意事项的列表。声音模组出现任何错误都会导致整个模组无法加载，其中所有声音均不会播放。

    代码 含义
    asset_path 路径不受支持、文件缺失、路径中存在文件夹冲突，或检测到链接。
    asset_format 文件类型不受支持：扩展名不符、Opus、浮点 WAV、8 位音频、采样率或声道数不在允许范围内，或 OGG 含有多条流。
    asset_budget 超出大小或数量限制：文件大小、时长、文件数、资源数或绑定数、解码后大小，或含资源的模组数量。
    asset_decode 文件损坏或不完整：文件被截断、数据块或页面范围超出文件、校验和错误，或加载声音时解码器失败。
    asset_conflict 两个模组绑定了同一提示音，或两个模组文件夹具有相同 ID。
    asset_binding 绑定或资源声明有误：提示音或资源未知、提示音重复绑定、ID 重复使用、增益超出 -24 至 0，或模组包含资源但不是 pack。
    asset_license 资源缺少 license 或 author。
    asset_capability 模组使用资源，但未在 requires 中列出 assets.audio.v1。如果模组需要此游戏不支持的功能，会显示单独警告并指出该功能。
    asset_normalized 注意事项：游戏降低了过响声音的音量。
    asset_changed 文件在游戏检查后、加载前发生了变化。请按重新加载。

    存档与已移除的模组¶

    存档会列出曾在该存档中启用的模组，并记录其文件哈希。之后移除声音模组时，存档仍会正常载入，游戏仍会显示该存档曾使用模组，提示音则会恢复为游戏自带声音。声音不会影响游戏经济或成就。
